## تعریف یک متد

در اینجا مثالی از یک اعلان متد معمولی آورده شده است:

```Java
public double calculateAnswer(double wingSpan, int numberOfEngines,
                              double length, double grossTons) {
    // محاسبات اینجا انجام می‌شود
}
```

تنها عناصر الزامی برای اعلان یک متد عبارتند از: نوع بازگشتی (return type)، نام متد، یک جفت پرانتز `()` و یک بدنه بین ابروها `{}`. به طور کلی، اعلان متد دارای ۶ جزء است که به ترتیب عبارتند از:

1. **اصلاح‌گرها (Modifiers):** مانند `public` ، `private` و موارد دیگر.
    
2. **نوع بازگشتی (Return type):** نوع داده مقداری که توسط متد برگردانده می‌شود، یا `void` اگر متد مقداری برنمی‌گرداند.
    
3. **نام متد:** قوانین نام‌گذاری فیلدها در اینجا نیز صدق می‌کند، اما قراردادها کمی متفاوت است.
    
4. **لیست پارامترها در داخل پرانتز:** لیستی از پارامترهای ورودی که با ویرگول از هم جدا شده و قبل از هر کدام نوع داده آن می‌آید. اگر پارامتری وجود ندارد، باید از پرانتز خالی استفاده کنید.
    
5. **لیست استثناها (Exception list):** که بعداً بررسی خواهد شد.
    
6. **بدنه متد:** کدهای متد، از جمله اعلان متغیرهای محلی، در اینجا قرار می‌گیرند.

> **تعریف:** دو مورد از اجزای اعلان متد، **امضای متد (Method Signature)** را تشکیل می‌دهند: **نام متد** و **نوع پارامترها**.

امضای متد ذکر شده در بالا به این صورت است:

`calculateAnswer(double, int, double, double)`

---

#### نام‌گذاری یک متد

اگرچه نام متد می‌تواند هر شناسه قانونی باشد، اما قراردادهای کدنویسی محدودیت‌هایی را اعمال می‌کنند. طبق قرارداد، نام متد باید یک **فعل** با حروف کوچک باشد یا یک نام چندکلمه‌ای که با یک فعل با حروف کوچک شروع شده و در ادامه با صفت، اسم و غیره همراه شود. در نام‌های چندکلمه‌ای، حرف اول کلمه دوم و کلمات بعدی باید بزرگ باشد (CamelCase). مثال:

- `run`
    
- `runFast`
    
- `getBackground`
    
- `isEmpty`

معمولاً یک متد در کلاس خود نامی منحصربه‌فرد دارد، اما ممکن است به دلیل **سربارگذاری متد (Method Overloading)**، نامی مشابه با متدهای دیگر داشته باشد.

---

#### سربارگذاری متدها (Overloading Methods)

زبان برنامه‌نویسی جاوا از سربارگذاری متدها پشتیبانی می‌کند و می‌تواند بین متدهایی با امضاهای متفاوت تمایز قائل شود. این بدان معناست که متدهای درون یک کلاس می‌توانند نام یکسانی داشته باشند، به شرطی که **لیست پارامترهای آن‌ها متفاوت باشد**.

فرض کنید کلاسی دارید که داده‌های مختلف (رشته، عدد صحیح و غیره) را ترسیم می‌کند. استفاده از نام‌های مختلف مانند `drawString` یا `drawInteger` دشوار است. در جاوا، می‌توانید برای همه این‌ها از نام `draw` استفاده کنید، اما لیست آرگومان‌های متفاوتی را به هر کدام پاس بدهید:

```Java
public class DataArtist {
    public void draw(String s) { ... }
    public void draw(int i) { ... }
    public void draw(double f) { ... }
    public void draw(int i, double f) { ... }
}
```

متدهای سربارگذاری شده بر اساس **تعداد** و **نوع** آرگومان‌های ورودی از هم تفکیک می‌شوند. شما نمی‌توانید بیش از یک متد با نام و لیست پارامترهای کاملاً یکسان تعریف کنید، زیرا کامپایلر نمی‌تواند آن‌ها را از هم تشخیص دهد.

**نکته مهم:** کامپایلر در هنگام تفکیک متدها، **نوع بازگشتی را در نظر نمی‌گیرد**؛ بنابراین نمی‌توانید دو متد با امضای یکسان (نام و پارامترهای برابر) داشته باشید، حتی اگر نوع بازگشتی آن‌ها متفاوت باشد.

> **توجه:** از متدهای سربارگذاری شده باید با احتیاط استفاده کرد، زیرا می‌توانند خوانایی کد را به شدت کاهش دهند.
