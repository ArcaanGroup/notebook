## ارسال اطلاعات به یک متد یا سازنده

اعلان یک متد یا سازنده، تعداد و نوع آرگومان‌های مورد نیاز را تعیین می‌کند. برای مثال، متد زیر اقساط ماهیانه یک وام مسکن را بر اساس مبلغ وام، نرخ بهره، مدت زمان وام (تعداد دوره‌ها) و ارزش آتی وام محاسبه می‌کند:

```Java
public double computePayment(
                  double loanAmt,
                  double rate,
                  double futureValue,
                  int numPeriods) {
    double interest = rate / 100.0;
    double partial1 = Math.pow((1 + interest), - numPeriods);
    double denominator = (1 - partial1) / interest;
    double answer = (-loanAmt / denominator)
                    - ((futureValue * partial1) / denominator);
    return answer;
}
```

این متد دارای چهار **پارامتر** است: مبلغ وام، نرخ بهره، ارزش آتی و تعداد دوره‌ها. سه مورد اول اعداد اعشاری با دقت مضاعف (`double`) و چهارمین مورد یک عدد صحیح (`int`) است. این پارامترها در بدنه متد استفاده می‌شوند و در زمان اجرا، مقادیر **آرگومان‌هایی** را که به متد پاس داده شده‌اند، به خود می‌گیرند.

> **نکته:** **پارامترها (Parameters)** به لیست متغیرها در اعلان متد اشاره دارند. **آرگومان‌ها (Arguments)** مقادیر واقعی هستند که هنگام فراخوانی متد به آن پاس داده می‌شوند. هنگام فراخوانی، آرگومان‌های استفاده شده باید از نظر **نوع** و **ترتیب** با پارامترهای اعلان شده مطابقت داشته باشند.

---

#### انواع پارامترها

شما می‌توانید از هر نوع داده‌ای برای پارامترهای یک متد یا سازنده استفاده کنید. این شامل انواع داده‌های اولیه (`primitive`) مانند اعداد اعشاری و صحیح (که در متد `computePayment` دیدید) و انواع داده‌های مرجع (`reference`) مانند اشیاء و آرایه‌ها می‌شود.

در اینجا مثالی از متدی آورده شده است که یک **آرایه** را به عنوان آرگومان می‌پذیرد. در این مثال، متد یک شیء جدید از نوع `Polygon` ایجاد کرده و آن را با استفاده از آرایه‌ای از اشیاء `Point` مقداردهی اولیه می‌کند:

```Java
public Polygon polygonFrom(Point[] corners) {
    // بدنه متد اینجا قرار می‌گیرد
}
```

### تعداد متغیر آرگومان‌ها (Varargs)

شما می‌توانید از ساختاری به نام **varargs** استفاده کنید تا تعداد دلخواهی از مقادیر را به یک متد پاس دهید. زمانی از varargs استفاده می‌شود که نمی‌دانید چه تعداد از یک نوع خاص آرگومان به متد پاس داده خواهد شد. این قابلیت در واقع یک میان‌بر برای ساخت دستی آرایه است.

برای استفاده از varargs، پس از تعیین نوعِ آخرین پارامتر، سه نقطه (`...`)، سپس یک فاصله و بعد نام پارامتر را قرار می‌دهید. متد را می‌توان با هر تعداد از آن پارامتر (حتی صفر عدد) فراخوانی کرد.

```Java
public Polygon polygonFrom(Point... corners) {
    int numberOfSides = corners.length;
    double squareOfSide1, lengthOfSide1;
    // با پارامتر corners مانند یک آرایه رفتار می‌شود
    squareOfSide1 = (corners[1].x - corners[0].x)
                     * (corners[1].x - corners[0].x) 
                     + (corners[1].y - corners[0].y)
                     * (corners[1].y - corners[0].y);
    lengthOfSide1 = Math.sqrt(squareOfSide1);

    // بدنه متد برای ایجاد و بازگرداندن چندضلعی ادامه می‌یابد
}
```

همان‌طور که مشاهده می‌کنید، در داخل متد با `corners` مانند یک آرایه رفتار می‌شود. این متد را می‌توان هم با یک آرایه و هم با توالی از آرگومان‌ها فراخوانی کرد. بیشترین کاربرد varargs در متدهای چاپ دیده می‌شود؛ مانند متد `printf()`:

```Java
public PrintStream printf(String format, Object... args)
```

این متد به شما اجازه می‌دهد تعداد دلخواهی از اشیاء را چاپ کنید:

`System.out.printf("%s: %d, %s%n", name, idnum, address);`

### نام پارامترها (Parameter Names)

هنگامی که پارامتری را برای یک متد یا سازنده اعلان می‌کنید، نامی برای آن در نظر می‌گیرید که در بدنه متد برای ارجاع به آرگومان پاس داده شده استفاده می‌شود.

نام پارامتر باید در محدوده (scope) خود منحصربه‌فرد باشد. این نام نمی‌تواند با نام پارامتر دیگری در همان متد، یا نام یک متغیر محلی در داخل همان متد یکسان باشد.

#### پنهان‌سازی فیلد (Shadowing)

یک پارامتر می‌تواند هم‌نام با یکی از فیلدهای کلاس باشد. در این صورت، اصطلاحاً گفته می‌شود که پارامتر، فیلد را **shadow** (پنهان) کرده است. این کار می‌تواند خوانایی کد را کاهش دهد و طبق قرارداد، معمولاً فقط در سازنده‌ها یا متدهایی که مقدار یک فیلد خاص را تنظیم می‌کنند (Setters) استفاده می‌شود. کلاس `Circle` را در نظر بگیرید:

```Java
public class Circle {
    private int x, y, radius;
    public void setOrigin(int x, int y) {
        // x و y در اینجا به پارامترها اشاره دارند، نه به فیلدها
    }
}
```

در بدنه متد `setOrigin` ، استفاده از نام‌های ساده `x` یا `y` به پارامترها اشاره دارد. برای دسترسی به فیلدها در این شرایط، باید از یک نام واجد شرایط (qualified name) استفاده کنید که در بخش مربوط به کلمه کلیدی `this` بررسی خواهد شد.

### ارسال آرگومان‌های نوع داده اولیه (Passing Primitive Data Types)

در جاوا، آرگومان‌های اولیه مانند `int` یا `double` به صورت **ارسال با مقدار (Pass by Value)** به متدها پاس داده می‌شوند. این بدان معناست که هر تغییری در مقدار پارامترها فقط در محدوده (Scope) همان متد باقی می‌ماند. هنگامی که متد به پایان می‌رسد، پارامترها از بین می‌روند و هر تغییری در آن‌ها از دست می‌رود.

به مثال زیر دقت کنید:

```Java
public class PassPrimitiveByValue {
    public static void main(String[] args) {
        int x = 3;
        // فراخوانی متد با آرگومان x
        passMethod(x);
        // چاپ x برای بررسی تغییر مقدار
        IO.println("After invoking passMethod, x = " + x);
    }
        
    public static void passMethod(int p) {
        p = 10; // تغییر پارامتر در داخل متد
    }
}
```

خروجی این برنامه عدد **۳** است، زیرا متد تنها روی یک "کپی" از مقدار عمل کرده است.

### ارسال آرگومان‌های نوع داده مرجع (Passing Reference Data Types)

پارامترهای نوع مرجع، مانند **اشیاء (Objects)**، نیز به صورت **ارسال با مقدار** پاس داده می‌شوند. اما نکته ظریف اینجاست: "مقداری" که پاس داده می‌شود، در واقع **آدرس (Reference)** آن شیء در حافظه است.

این به دو معناست:

1. **تغییر فیلدها:** اگر فیلدهای شیء را در متد تغییر دهید، این تغییرات **ماندگار** هستند، چون هر دو (آرگومان اصلی و پارامتر متد) به یک شیء واحد در حافظه اشاره می‌کنند.
    
2. **تغییر خودِ مرجع:** اگر داخل متد، پارامتر را به یک شیء جدید منتسب کنید (مثلاً با `new`)، این تغییر به بیرون از متد منتقل نمی‌شود.

مثال متد جابه‌جایی دایره:

```Java
public void moveCircle(Circle circle, int deltaX, int deltaY) {
    // تغییر مختصات شیء (تغییر ماندگار است)
    circle.setX(circle.getX() + deltaX);
    circle.setY(circle.getY() + deltaY);
        
    // انتساب یک مرجع جدید به پارامتر (تغییر ماندگار نیست)
    circle = new Circle(0, 0);
}
```

وقتی متد `moveCircle(myCircle, 23, 56)` را فراخوانی می‌کنید:

- مختصات `myCircle` با موفقیت تغییر می‌کند.
    
- اما دستور `circle = new Circle(0, 0)` باعث نمی‌شود که `myCircle` در بیرون از متد به دایره جدید اشاره کند. `myCircle` همچنان به همان شیء قبلی اشاره دارد.
