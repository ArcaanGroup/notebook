این بخش به جنبه‌های پیشرفته‌تری از کلاس‌ها می‌پردازد که بر پایه درک شما از مراجع اشیاء (Object References) و عملگر نقطه (`.`) بنا شده است. مباحث شامل موارد زیر است:

- بازگرداندن مقادیر از متدها
    
- کلمه کلیدی `this`
    
- اعضای کلاس در مقابل اعضای نمونه (Class vs. Instance Members)
    
- کنترل سطح دسترسی (Access Control)

---

### بازگرداندن مقدار از یک متد (Returning a Value from a Method)

یک متد زمانی به کدی که آن را فراخوانی کرده بازمی‌گردد که یکی از حالات زیر رخ دهد:

1. تمام دستورات متد به پایان برسد.
    
2. به دستور `return` برسد.
    
3. یک استثنا (Exception) پرتاب کند (که بعداً بررسی می‌شود).

#### متدهای بدون بازگشت (void)

متدهایی که با کلمه `void` اعلان می‌شوند، مقداری را برنمی‌گردانند. این متدها لزوماً نیازی به دستور `return` ندارند، اما می‌توان از آن برای خروج زودهنگام از متد (مثلاً بر اساس یک شرط) استفاده کرد:

```Java
public void checkStatus(int value) {
    if (value < 0) {
        return; // خروج از متد بدون بازگرداندن مقدار
    }
    // سایر دستورات
}
```

تلاش برای بازگرداندن یک مقدار در متد `void` منجر به خطای کامپایل می‌شود.

#### متدهای دارای مقدار بازگشتی

هر متدی که `void` نباشد، **باید** شامل یک دستور `return` به همراه مقداری متناسب با نوع اعلام شده باشد:

```Java
return returnValue;
```

نوع داده مقدار بازگشتی باید دقیقاً با نوع اعلام شده در امضای متد مطابقت داشته باشد (مثلاً نمی‌توانید در متدی که خروجی آن `boolean` است، عدد صحیح برگردانید).

#### بازگرداندن انواع مرجع (Reference Types)

یک متد علاوه بر انواع اولیه، می‌تواند یک **شیء** را نیز بازگرداند. برای مثال در کلاس دوچرخه:

```Java
public Bicycle seeWhosFastest(Bicycle myBike, Bicycle yourBike) {
    Bicycle fastest;
    // کدهایی برای محاسبه سریع‌ترین دوچرخه
    return fastest; // بازگرداندن مرجع یک شیء از نوع Bicycle
}
```

زمانی که یک متد یک شیء را برمی‌گرداند، در واقع **آدرس (مرجع)** آن شیء را به کد فراخوان تحویل می‌دهد.

---
### بازگرداندن یک کلاس یا رابط (Returning a Class or Interface)

اگر این بخش برایتان کمی پیچیده به نظر می‌رسد، می‌توانید فعلاً از آن عبور کنید و پس از مطالعه بخش **رابط‌ها (Interfaces)** و **وراثت (Inheritance)** دوباره به آن بازگردید.

زمانی که یک متد، نام یک کلاس را به عنوان **نوع بازگشتی** خود استفاده می‌کند (مانند متد `seeWhosFastest`)، شیئی که بازگردانده می‌شود باید یا از **خودِ آن کلاس** باشد و یا از **زیرکلاس‌های (Subclasses)** آن.

فرض کنید یک سلسله مراتب کلاسی دارید که در آن کلاس `ImaginaryNumber` زیرکلاسی از `java.lang.Number` است و خودِ کلاس `Number` نیز زیرکلاسی از `Object` محسوب می‌شود (مطابق تصویر بالا). 

![[03_class-hierarchy-imaginary.png]]
**سلسله مراتب کلاس `اعداد موهومی`**
***

حالا فرض کنید متدی دارید که به این صورت اعلان شده تا یک `Number` برگرداند:

```Java
public Number returnANumber() {
    ...
}
```

متد `returnANumber()` می‌تواند یک `ImaginaryNumber` برگرداند اما نمی‌تواند یک `Object` برگرداند. یک نمونه از `ImaginaryNumber` در واقع یک نمونه از `Number` هم هست (چون زیرکلاس آن است). اما یک `Object` لزوماً یک `Number` نیست؛ ممکن است یک رشته (`String`) یا هر نوع دیگری باشد.

#### نوع بازگشتی کوواریانت (Covariant Return Type)

شما می‌توانید یک متد را بازنویسی (Override) کنید و آن را به گونه‌ای تعریف کنید که زیرکلاسی از متد اصلی را برگرداند:
	
```Java
public ImaginaryNumber returnANumber() {
    ...
}
```

این تکنیک که **نوع بازگشتی کوواریانت** نامیده می‌شود، به این معناست که نوع بازگشتی مجاز است در همان جهتِ زیرکلاس تغییر کند.

> **نکته:** شما همچنین می‌توانید از نام **رابط‌ها (Interfaces)** به عنوان نوع بازگشتی استفاده کنید. در این صورت، شیء بازگردانده شده باید حتماً آن رابط مشخص را **پیاده‌سازی (Implement)** کرده باشد.

### استفاده از کلمه کلیدی this (Using the this Keyword)

در جاوا، کلمه کلیدی `this` مرجعی به **شیء فعلی** (current object) است؛ یعنی همان شیئی که متد یا سازنده آن در حال فراخوانی است. شما می‌توانید با استفاده از `this` در داخل یک متد نمونه یا سازنده، به هر یک از اعضای شیء فعلی ارجاع دهید.

---

#### استفاده از this در فیلدها (Using this with a Field)

رایج‌ترین دلیل استفاده از کلمه کلیدی `this` زمانی است که یک فیلد توسط پارامترِ متد یا سازنده پنهان (**Shadowed**) شده باشد.

کلاس `Point` را در نظر بگیرید که قبلاً به این صورت نوشته شده بود:

```Java
public class Point {
    public int x = 0;
    public int y = 0;
        
    public Point(int a, int b) {
        x = a; // نام پارامترها (a, b) با فیلدها متفاوت است
        y = b;
    }
}
```

اما می‌توان آن را به شکل زیر (که خواناتر است) نوشت:

```Java
public class Point {
    public int x = 0;
    public int y = 0;
        
    public Point(int x, int y) {
        this.x = x; // this.x به فیلد کلاس و x به پارامتر ورودی اشاره دارد
        this.y = y;
    }
}
```

در این حالت، هر آرگومانِ سازنده، فیلدِ هم‌نام خود را پنهان می‌کند. در داخل سازنده، `x` یک کپی محلی از اولین آرگومان است. برای ارجاع به فیلد `x` در کلاس `Point` سازنده باید از `this.x` استفاده کند.

---

#### استفاده از this در سازنده (Using this with a Constructor)

در داخل یک سازنده، می‌توانید از `this` برای فراخوانی سازنده دیگری در **همان کلاس** استفاده کنید. به این کار «فراخوانی صریح سازنده» (Explicit Constructor Invocation) می‌گویند.

در اینجا نسخه دیگری از کلاس `Rectangle` را با پیاده‌سازی متفاوت مشاهده می‌کنید:

```Java
public class Rectangle {
    private int x, y;
    private int width, height;
        
    public Rectangle() {
        this(0, 0, 1, 1); // فراخوانی سازنده چهار پارامتری با مقادیر پیش‌فرض
    }
    public Rectangle(int width, int height) {
        this(0, 0, width, height); // فراخوانی سازنده اصلی
    }
    public Rectangle(int x, int y, int width, int height) {
        this.x = x;
        this.y = y;
        this.width = width;
        this.height = height;
    }
}
```

این کلاس شامل مجموعه‌ای از سازنده‌هاست که هر کدام بخشی از متغیرهای عضو را مقداردهی می‌کنند. سازنده‌ها برای متغیرهایی که مقدارشان در آرگومان نیامده، مقدار پیش‌فرض در نظر می‌گیرند.

- سازنده بدون آرگومان، یک مستطیل $1 \times 1$ در مختصات $(0,0)$ ایجاد می‌کند.
    
- سازنده دو آرگومانی، سازنده چهار آرگومانی را فراخوانی کرده و مختصات را همیشه $(0,0)$ می‌فرستد.

> **نکته مهم:** اگر از `this()` برای فراخوانی سازنده دیگری استفاده می‌کنید، این دستور **حتماً باید اولین خط** در بدنه سازنده باشد.

### کنترل دسترسی به اعضای یک کلاس (Access Control)

اصلاح‌گرهای سطح دسترسی (Access Level Modifiers) تعیین می‌کنند که آیا کلاس‌های دیگر می‌توانند از یک فیلد خاص استفاده کنند یا متدی را فراخوانی کنند یا خیر. جاوا دو سطح کنترل دسترسی دارد:

1. **در سطح بالا (Top-level):** برای خودِ کلاس (`public` یا بدون اصلاح‌گر).
    
2. **در سطح عضو (Member-level):** برای فیلدها و متدها (`public` ، `private` ، `protected` یا بدون اصلاح‌گر).
    

#### دسترسی در سطح کلاس

- **public:** کلاس برای تمامی کلاس‌ها در هر جایی قابل مشاهده است.
    
- **بدون اصلاح‌گر (Default/Package-private):** کلاس فقط در داخل پکیج خودش قابل مشاهده است.

#### دسترسی در سطح اعضا

برای متغیرها و متدها، علاوه بر موارد بالا، دو اصلاح‌گر دیگر نیز وجود دارد:

- **private:** عضو فقط در داخل کلاس خودش قابل دسترسی است.
    
- **protected:** عضو در داخل پکیج خودش و همچنین توسط زیرکلاس‌ها (Subclasses) در پکیج‌های دیگر قابل دسترسی است.

---

### جدول سطوح دسترسی (Access Levels)

جدول زیر دسترسی مجاز برای هر اصلاح‌گر را نشان می‌دهد:

|**اصلاح‌گر (Modifier)**|**کلاس (Class)**|**پکیج (Package)**|**زیرکلاس (Subclass)**|**کل دنیا (World)**|
|---|---|---|---|---|
|**public**|Yes|Yes|Yes|Yes|
|**protected**|Yes|Yes|Yes|No|
|**بدون اصلاح‌گر**|Yes|Yes|No|No|
|**private**|Yes|No|No|No|

- **ستون اول:** نشان می‌دهد که کلاس همیشه به اعضای خودش دسترسی دارد.
    
- **ستون دوم:** نشان می‌دهد کلاس‌های هم‌رده در یک پکیج دسترسی دارند یا خیر.
    
- **ستون سوم:** نشان می‌دهد آیا زیرکلاس‌هایی که خارج از پکیج هستند دسترسی دارند یا خیر.
    
- **ستون چهارم:** نشان می‌دهد آیا هر کلاسی در هر پکیجی به آن عضو دسترسی دارد یا خیر.

---

### نکاتی برای انتخاب سطح دسترسی مناسب

اگر برنامه‌نویسان دیگر از کلاس شما استفاده می‌کنند، باید مطمئن شوید که خطاهای ناشی از استفاده نادرست رخ نمی‌دهد. سطوح دسترسی در این زمینه به شما کمک می‌کنند:

1. **سخت‌گیرانه‌ترین حالت را انتخاب کنید:** همیشه محدودترین سطح دسترسی را که منطقی است انتخاب کنید. تا زمانی که دلیل خوبی ندارید، از `private` استفاده کنید.
    
2. **از فیلدهای public دوری کنید:** به جز برای **ثابت‌ها (Constants)**، فیلدها را عمومی نکنید. فیلدهای عمومی انعطاف‌پذیری شما را در تغییر کد در آینده محدود می‌کنند و شما را به یک پیاده‌سازی خاص وابسته می‌سازند.
    
3. **کپسوله‌سازی (Encapsulation):** به جای عمومی کردن فیلدها، آن‌ها را `private` کرده و از متدهای `public` برای خواندن (`Getter`) یا تغییر (`Setter`) آن‌ها استفاده کنید.


### درک اعضای کلاس (Understanding Class Members)

در این بخش، به بررسی کلمه کلیدی **`static`** می‌پردازیم؛ ابزاری که به شما اجازه می‌دهد فیلدها و متدهایی ایجاد کنید که به خودِ **کلاس** تعلق دارند، نه به یک **نمونه (Instance)** خاص از آن کلاس.

---

### متغیرهای کلاس (Class Variables)

به طور معمول، وقتی چندین شیء از یک کلاس ساخته می‌شوند، هر کدام کپی‌های مجزای خود را از متغیرهای نمونه (Instance Variables) دارند. در کلاس `Bicycle` فیلدهایی مثل `speed` یا `gear` برای هر دوچرخه متفاوت است و در مکان‌های مختلفی از حافظه ذخیره می‌شود.

اما گاهی نیاز داریم متغیری داشته باشیم که بین تمام اشیاء **مشترک** باشد. این کار با استفاده از اصلاح‌گر **`static`** انجام می‌شود. فیلدهایی که دارای این کلمه کلیدی هستند، **متغیر کلاس** نامیده می‌شوند.

- **حافظه واحد:** تمام نمونه‌های کلاس، این متغیر را در یک مکان ثابت از حافظه به اشتراک می‌گذارند.
    
- **ارتباط با کلاس:** این متغیرها به جای اشیاء، با خودِ کلاس در ارتباط هستند.
    
- **تغییرپذیری:** هر شیئی می‌تواند مقدار آن را تغییر دهد، اما حتی بدون ساختن هیچ شیئی هم می‌توان به این متغیرها دسترسی داشت.

---

### مثال: مدیریت شماره سریال دوچرخه‌ها

فرض کنید می‌خواهید به هر دوچرخه یک شماره شناسایی (`id`) منحصربه‌فرد بدهید که از عدد ۱ شروع شود. همچنین نیاز دارید بدانید تا کنون چند دوچرخه ساخته شده است تا شماره بعدی را تعیین کنید.

- **`id`**: یک متغیر نمونه است (چون برای هر دوچرخه متفاوت است).
    
- **`numberOfBicycles`**: یک متغیر کلاس (static) است (چون مربوط به کل خط تولید یا همان کلاس است).

```Java
public class Bicycle {
    private int cadence;
    private int gear;
    private int speed;
    private int id; // متغیر نمونه

    // متغیر کلاس برای ردیابی تعداد کل اشیاء ساخته شده
    private static int numberOfBicycles = 0;

    public Bicycle(int startCadence, int startSpeed, int startGear) {
        gear = startGear;
        cadence = startCadence;
        speed = startSpeed;

        // افزایش تعداد کل دوچرخه‌ها و اختصاص ID به شیء فعلی
        id = ++numberOfBicycles;
    }

    public int getID() {
        return id;
    }
}
```

#### نحوه ارجاع به متغیرهای Static

بهترین راه برای دسترسی به این متغیرها، استفاده از **نام کلاس** است:

`Bicycle.numberOfBicycles`

> **نکته:** اگرچه می‌توانید با استفاده از مرجع یک شیء (مانند `myBike.numberOfBicycles`) هم به این فیلد دسترسی پیدا کنید، اما این کار به شدت **توصیه نمی‌شود**؛ زیرا تشخیص اینکه متغیر متعلق به کلاس است (و نه آن شیء خاص) را دشوار می‌کند.

---

### خلاصه تفاوت‌ها

|**ویژگی**|**متغیر نمونه (Instance Variable)**|**متغیر کلاس (Static Variable)**|
|---|---|---|
|**تعریف**|بدون کلمه `static`|دارای کلمه `static`|
|**محل ذخیره**|در هر شیء به صورت جداگانه|یک بار در حافظه برای کل کلاس|
|**دسترسی**|از طریق نام شیء (`obj.var`)|از طریق نام کلاس (`Class.var`)|
|**زمان ایجاد**|هنگام ساخت شیء با `new`|هنگام بارگذاری کلاس توسط JVM|

### متدهای کلاس (Class Methods)

زبان برنامه‌نویسی جاوا علاوه بر متغیرهای استاتیک، از **متدهای استاتیک** نیز پشتیبانی می‌کند. این متدها که با کلمه کلیدی `static` در اعلان خود مشخص می‌شوند، باید با استفاده از **نام کلاس** و بدون نیاز به ایجاد نمونه‌ای از آن فراخوانی شوند:

```Java
ClassName.methodName(args)
```

> **نکته:** مشابه متغیرهای استاتیک، فراخوانی این متدها از طریق مرجع یک شیء (مثلاً `myBike.getNumberOfBicycles()`) نیز امکان‌پذیر است، اما این کار **توصیه نمی‌شود**؛ زیرا تشخیص استاتیک بودن متد را برای خواننده کد دشوار می‌کند.

رایج‌ترین کاربرد متدهای استاتیک، دسترسی به فیلدهای استاتیک است. برای مثال در کلاس `Bicycle`:

```Java
public static int getNumberOfBicycles() {
    return numberOfBicycles;
}
```

#### محدودیت‌های دسترسی اعضا (Instance vs. Class)

ترکیب دسترسی اعضای استاتیک و غیر استاتیک دارای قوانین مشخصی است:

1. **متدهای نمونه (Instance Methods):** می‌توانند به متغیرها و متدهای نمونه و همچنین متغیرها و متدهای کلاس (static) به طور مستقیم دسترسی داشته باشند.
    
2. **متدهای کلاس (Static Methods):**
    
    - می‌توانند به متغیرها و متدهای استاتیک به طور مستقیم دسترسی داشته باشند.
        
    - **نمی‌توانند** به متغیرها یا متدهای نمونه به طور مستقیم دسترسی پیدا کنند (مگر اینکه ابتدا یک شیء بسازند و از طریق آن اقدام کنند).
        
    - **نمی‌توانند** از کلمه کلیدی `this` استفاده کنند، زیرا در سطح کلاس هستند و "نمونه فعلی" برای آن‌ها وجود ندارد.

---

### ثابت‌ها (Constants)

ترکیب اصلاح‌گر `static` با `final` برای تعریف **ثابت‌ها** استفاده می‌شود. کلمه `final` نشان می‌دهد که مقدار این فیلد پس از مقداردهی اولیه، دیگر قابل تغییر نیست.

```Java
static final double PI = 3.141592653589793;
```

تلاش برای تغییر مقدار یک ثابت باعث خطای زمان کامپایل می‌شود. طبق قرارداد، نام ثابت‌ها با **حروف بزرگ** نوشته می‌شود و کلمات با علامت خط تیره زیرین (`_`) از هم جدا می‌شوند.

> **ثابت‌های زمان کامپایل:** اگر مقدار یک ثابت در زمان کامپایل مشخص باشد، کامپایلر نام ثابت را در کل کد با مقدار واقعی آن جایگزین می‌کند. اگر مقدار چنین ثابتی در دنیای واقعی تغییر کند، باید تمام کلاس‌هایی را که از آن استفاده کرده‌اند دوباره کامپایل کنید.

---

### کلاس نهایی Bicycle

پس از اعمال تمام تغییرات این بخش، کلاس `Bicycle` به شکل کامل زیر در می‌آید که ترکیبی از اعضای نمونه (برای ویژگی‌های فردی هر دوچرخه) و اعضای کلاس (برای ردیابی کل اشیاء) است:

```Java
public class Bicycle {
    // فیلدهای نمونه
    private int cadence;
    private int gear;
    private int speed;
    private int id;
    
    // فیلد کلاس (مشترک بین همه)
    private static int numberOfBicycles = 0;

    public Bicycle(int startCadence, int startSpeed, int startGear) {
        gear = startGear;
        cadence = startCadence;
        speed = startSpeed;
        // اختصاص ID منحصر به فرد با استفاده از متغیر استاتیک
        id = ++numberOfBicycles;
    }

    public int getID() { return id; }

    public static int getNumberOfBicycles() {
        return numberOfBicycles;
    }
    
    // سایر متدهای Getter و Setter...
}
```

### مقداردهی اولیه فیلدها (Initializing Fields)

همان‌طور که مشاهده کردید، اغلب می‌توانید مقدار اولیه یک فیلد را هنگام اعلان آن تعیین کنید:

```Java
public class BedAndBreakfast {
    // مقداردهی اولیه به 10
    public static int capacity = 10;

    // مقداردهی اولیه به false
    private boolean full = false;
}
```

این روش زمانی عالی است که مقداردهی در یک خط قابل انجام باشد. اما اگر مقداردهی نیاز به منطق پیچیده‌تری داشته باشد (مثلاً مدیریت خطا، استفاده از حلقه `for` برای پر کردن یک آرایه یا دسترسی به دیتابیس)، انتساب ساده کافی نیست.

برای متغیرهای نمونه (Instance Variables)، می‌توان از **سازنده‌ها (Constructors)** استفاده کرد. اما برای متغیرهای کلاس (Class Variables)، جاوا قابلیت **بلاک‌های مقداردهی استاتیک** را ارائه می‌دهد.

---

### بلاک‌های مقداردهی استاتیک (Static Initialization Blocks)

یک بلاک استاتیک، مجموعه‌ای از کدهاست که داخل آکولاد `{ }` قرار گرفته و قبل از آن کلمه کلیدی `static` می‌آید.

```Java
static {
    // کدهای لازم برای مقداردهی اولیه در اینجا قرار می‌گیرند
}
```

- یک کلاس می‌تواند چندین بلاک استاتیک داشته باشد که در هر جای بدنه کلاس ظاهر شوند.
    
- سیستم زمان اجرا تضمین می‌کند که این بلاک‌ها به **ترتیب ظهور در کد منبع** فراخوانی شوند.
    
- این بلاک‌ها فقط **یک‌بار**، هنگام بارگذاری کلاس در حافظه (قبل از ساخت اولین شیء یا دسترسی به اولین متغیر استاتیک) اجرا می‌شوند.

#### جایگزین بلاک استاتیک: متدهای استاتیک خصوصی

می‌توانید به جای بلاک استاتیک، از یک متد استاتیک خصوصی استفاده کنید:

```Java
class Whatever {
    public static varType myVar = initializeClassVariable();
        
    private static varType initializeClassVariable() {
        // منطق مقداردهی در اینجا
        return someValue;
    }
}
```

**مزیت:** این متدها در صورت نیاز به مقداردهی مجدد در آینده، قابل بازاستفاده هستند.

**نکته امنیتی:** اگر کد داخل بلاک استاتیک به دلیل مشکلاتی مثل نبود دسترسی به فایل یا شبکه اجرا نشود، کلاس بارگذاری نخواهد شد و کل اپلیکیشن با مشکل مواجه می‌شود.

---

### مقداردهی اولیه اعضای نمونه (Initializing Instance Members)

معمولاً متغیرهای نمونه در سازنده مقداردهی می‌شوند، اما دو جایگزین دیگر وجود دارد:

#### ۱. بلاک‌های مقداردهی نمونه (Initializer Blocks)

این بلاک‌ها دقیقاً شبیه بلاک‌های استاتیک هستند اما کلمه `static` را ندارند:

```Java
{
    // کدهای مقداردهی برای هر شیء جدید
}
```

کامپایلر جاوا این بلاک‌ها را در ابتدای **هر سازنده** کپی می‌کند. این روش برای به اشتراک گذاشتن کدهای مشترک بین چندین سازنده بسیار مفید است.

#### ۲. متدهای نهایی (Final Methods)

استفاده از یک متد `final` برای مقداردهی اولیه:

```Java
class Whatever {
    private varType myVar = initializeInstanceVariable();
        
    protected final varType initializeInstanceVariable() {
        // کدهای مقداردهی
        return someValue;
    }
}
```

**چرا final؟** فراخوانی متدهای غیر‌نهایی (که قابل بازنویسی در زیرکلاس‌ها هستند) در طول فرآیند مقداردهی اولیه شیء می‌تواند باعث بروز رفتارهای پیش‌بینی نشده و خطا شود. استفاده از `final` اطمینان می‌دهد که رفتار مقداردهی در تمام زیرکلاس‌ها یکسان باقی می‌ماند.

### خلاصه ایجاد و استفاده از کلاس‌ها و اشیاء (Summary)

در این بخش، مفاهیم کلیدی که درباره ساختار کلاس‌ها و چرخه حیات اشیاء آموختیم را مرور می‌کنیم:

#### ۱. ساختار کلاس (Class Structure)

اعلان یک کلاس شامل نام کلاس و بدنه‌ای است که بین دو آکولاد `{ }` قرار می‌گیرد.

- **فیلدها (Fields):** برای ذخیره وضعیت (State) شیء.
    
- **متدها (Methods):** برای پیاده‌سازی رفتار (Behavior) شیء.
    
- **سازنده‌ها (Constructors):** برای مقداردهی اولیه نمونه‌های جدید. سازنده هم‌نام کلاس است و هیچ نوع بازگشتی (حتی `void`) ندارد.

#### ۲. کنترل دسترسی و اعضای استاتیک

- **اصلاح‌گرهای دسترسی:** با استفاده از کلماتی مانند `public` یا `private` کنترل می‌کنید که چه کدهایی به اعضای کلاس دسترسی داشته باشند.
    
- **اعضای کلاس (Static):** با کلمه کلیدی `static` مشخص می‌شوند. این اعضا بین تمام نمونه‌ها مشترک هستند و از طریق **نام کلاس** قابل دسترسی‌اند.
    
- **اعضای نمونه (Instance):** هر شیء کپی اختصاصی خود را از این اعضا دارد و فقط از طریق **مرجع شیء** (Object Reference) قابل دسترسی هستند.

#### ۳. ایجاد و استفاده از اشیاء

- **عملگر `new`:** برای ساخت شیء به کار می‌رود و یک **مرجع (Reference)** به آن شیء در حافظه برمی‌گرداند.
    
- **نام واجد شرایط (Qualified Name):** برای دسترسی به اعضای یک شیء از بیرون کلاس، از عملگر نقطه (`.`) استفاده می‌کنیم:
    
    - `objectReference.variableName`
        
    - `objectReference.methodName()`

#### ۴. مدیریت حافظه (Garbage Collection)

زباله‌روب جاوا به طور خودکار اشیائی را که دیگر هیچ مرجعی به آن‌ها وجود ندارد، پاکسازی می‌کند. شما می‌توانید با قرار دادن مقدار `null` در یک متغیر، مرجع به شیء را به صورت دستی قطع کنید تا شیء آماده حذف شود.
