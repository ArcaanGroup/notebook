### درک مفهوم اشیاء

یک برنامه معمولی جاوا اشیاء بسیاری ایجاد می‌کند که همان‌طور که می‌دانید، از طریق فراخوانی متدها با یکدیگر تعامل دارند. از طریق این تعاملات، برنامه می‌تواند وظایف مختلفی مانند اجرای یک رابط کاربری گرافیکی (GUI)، اجرای انیمیشن یا تبادل اطلاعات در شبکه را انجام دهد. هنگامی که یک شیء وظیفه‌ای را که برای آن ساخته شده به پایان می‌رساند، منابع آن برای استفاده توسط اشیاء دیگر بازیافت می‌شود.

در ادامه، برنامه کوچکی به نام `CreateObjectDemo` آورده شده است که سه شیء ایجاد می‌کند: یک شیء از کلاس `Point` و دو شیء از کلاس `Rectangle`.

```Java
public class CreateObjectDemo {
    public static void main(String[] args) {
        
        // اعلان و ایجاد یک نقطه و دو مستطیل
        Point originOne = new Point(23, 94);
        Rectangle rectOne = new Rectangle(originOne, 100, 200);
        Rectangle rectTwo = new Rectangle(50, 100);
        
        // نمایش ویژگی‌های rectOne
        IO.println("Width of rectOne: " + rectOne.width);
        IO.println("Height of rectOne: " + rectOne.height);
        IO.println("Area of rectOne: " + rectOne.getArea());
        
        // تنظیم موقعیت rectTwo
        rectTwo.origin = originOne;
        
        // نمایش موقعیت rectTwo
        IO.println("X Position of rectTwo: " + rectTwo.origin.x);
        IO.println("Y Position of rectTwo: " + rectTwo.origin.y);
        
        // جابه‌جایی rectTwo و نمایش موقعیت جدید
        rectTwo.move(40, 72);
        IO.println("X Position of rectTwo: " + rectTwo.origin.x);
        IO.println("Y Position of rectTwo: " + rectTwo.origin.y);
    }
}
```

#### کلاس‌های مورد نیاز

برای اجرای کد بالا، به دو کلاس زیر نیاز داریم:

**کلاس Point:**

```Java
public class Point {
    public int x = 0;
    public int y = 0;
    public Point(int a, int b) {
        x = a;
        y = b;
    }
}
```

**کلاس Rectangle:**

```Java
public class Rectangle {
    public int width = 0;
    public int height = 0;
    public Point origin;
 
    // چهار سازنده مختلف (Overloading)
    public Rectangle() { origin = new Point(0, 0); }
    public Rectangle(Point p) { origin = p; }
    public Rectangle(int w, int h) {
        origin = new Point(0, 0);
        width = w;
        height = h;
    }
    public Rectangle(Point p, int w, int h) {
        origin = p;
        width = w;
        height = h;
    }
 
    public void move(int x, int y) {
        origin.x = x;
        origin.y = y;
    }
 
    public int getArea() {
        return width * height;
    }
}
```

```
Y Position of rectTwo: 72
```

### چرخه حیات یک شیء

مثال بالا نشان‌دهنده سه مرحله اصلی در زندگی یک شیء است که در بخش‌های بعدی به تفصیل بررسی خواهیم کرد:

1. **اعلان (Declaration):** اختصاص یک نام متغیر به یک نوع شیء.
    
2. **نمونه‌سازی (Instantiation):** استفاده از کلمه کلیدی `new` برای ایجاد شیء.
    
3. **مقداردهی اولیه (Initialization):** فراخوانی سازنده برای تنظیم وضعیت اولیه شیء.

### ایجاد اشیاء (Creating Objects)

همان‌طور که می‌دانید، کلاس طرح اولیه (Blueprint) یک شیء را ارائه می‌دهد و شما اشیاء را از روی کلاس‌ها می‌سازید. هر یک از جملات زیر که از برنامه `CreateObjectDemo` برداشته شده‌اند، یک شیء ایجاد کرده و آن را به یک متغیر نسبت می‌دهند:

```Java
Point originOne = new Point(23, 94);
Rectangle rectOne = new Rectangle(originOne, 100, 200);
Rectangle rectTwo = new Rectangle(50, 100);
```

هر یک از این جملات دارای سه بخش اساسی است:

1. **اعلان (Declaration):** کدهایی که نام متغیر را با یک نوع شیء مرتبط می‌کنند.
    
2. **نمونه‌سازی (Instantiation):** کلمه کلیدی `new` یک عملگر جاوا است که شیء را ایجاد می‌کند.
    
3. **مقداردهی اولیه (Initialization):** عملگر `new` با فراخوانی یک سازنده (Constructor) دنبال می‌شود که وضعیت اولیه شیء را تنظیم می‌کند.

---

### اعلان متغیر برای ارجاع به یک شیء

پیش از این آموختید که برای اعلان یک متغیر می‌نویسیم: `type name;`. این کار به کامپایلر اعلام می‌کند که شما از `name` برای ارجاع به داده‌ای از نوع `type` استفاده خواهید کرد. در متغیرهای اولیه (Primitive)، این اعلان مقدار مناسبی از حافظه را نیز رزرو می‌کند.

شما می‌توانید یک متغیر مرجع (Reference Variable) را در یک خط جداگانه اعلان کنید:

```Java
Point originOne;
```

اگر `originOne` را به این صورت اعلان کنید، مقدار آن تا زمانی که شیئی واقعاً ایجاد و به آن نسبت داده نشود، نامشخص خواهد بود. صرفاً اعلان یک متغیر مرجع، شیء ایجاد نمی‌کند. برای این کار باید از عملگر `new` استفاده کنید. اگر پیش از نسبت دادن شیء به `originOne` از آن در کد استفاده کنید، با خطای کامپایلر مواجه خواهید شد. متغیر در این حالت به هیچ شیئی ارجاع نمی‌دهد.

---

### نمونه‌سازی از یک کلاس (Instantiating a Class)

عملگر `new` با تخصیص حافظه برای یک شیء جدید و بازگرداندن یک **مرجع (Reference)** به آن حافظه، از کلاس نمونه‌سازی می‌کند. این عملگر همچنین سازنده شیء را فراخوانی می‌کند.

> **نکته:** عبارت "نمونه‌سازی از یک کلاس" دقیقاً به معنای "ایجاد یک شیء" است. وقتی شیئی می‌سازید، در واقع یک "نمونه" (Instance) از کلاس ایجاد می‌کنید.

عملگر `new` به یک آرگومان نیاز دارد: **فراخوانی سازنده**. نام سازنده، نام کلاسی را که باید از آن نمونه‌سازی شود مشخص می‌کند. مرجع بازگردانده شده توسط `new` معمولاً به متغیری از نوع مناسب نسبت داده می‌شود، اما اجباری به این کار نیست. مرجع می‌تواند مستقیماً در یک عبارت استفاده شود:

```Java
int height = new Rectangle().height;
```

### مقداردهی اولیه یک شیء (Initializing an Object)

کد کلاس `Point` را در نظر بگیرید:

```Java
public class Point {
    public int x = 0;
    public int y = 0;
    // سازنده
    public Point(int a, int b) {
        x = a;
        y = b;
    }
}
```

این کلاس شامل یک سازنده است. سازنده با نام کلاس هم‌خوانی دارد و نوع بازگشتی ندارد. سازنده `Point` دو آرگومان صحیح می‌گیرد. دستور زیر مقادیر ۲۳ و ۹۴ را برای این آرگومان‌ها فراهم می‌کند:

```Java
Point originOne = new Point(23, 94);
```

![[01_new-object.png]]
**یک شئ نقطه**
***

کلاس `Rectangle` دارای چهار سازنده مختلف است که به شما اجازه می‌دهند مقادیر اولیه برای مبدأ (`origin`)، عرض (`width`) و ارتفاع (`height`) مستطیل را با استفاده از انواع داده‌های اولیه و مرجع فراهم کنید.

همان‌طور که در متن اشاره شد، اگر کلاسی چندین سازنده داشته باشد، آن‌ها باید **امضاهای (Signatures)** متفاوتی داشته باشند. کامپایلر جاوا سازنده‌ها را بر اساس **تعداد** و **نوع** آرگومان‌ها از هم تشخیص می‌دهد.

#### تحلیل فراخوانی سازنده‌ها:

- **فراخوانی با سه آرگومان:**
    
    ```Java
    Rectangle rectOne = new Rectangle(originOne, 100, 200);
    ```
    
    در این حالت، کامپایلر متوجه می‌شود که باید سازنده‌ای را فراخوانی کند که یک `Point` و دو `int` دریافت می‌کند. در اینجا، متغیر `origin` در مستطیل به همان شیء `originOne` اشاره می‌کند. یعنی اکنون **دو مرجع** به یک شیء واحد `Point` در حافظه وجود دارد.
    
- **فراخوانی با دو آرگومان:**
    
    ```Java
    Rectangle rectTwo = new Rectangle(50, 100);
    ```
    
    این دستور سازنده‌ای را اجرا می‌کند که طول و عرض را تنظیم کرده و یک شیء **جدید** `Point` با مختصات (0,0) برای مبدأ ایجاد می‌کند.
    
- **سازنده بدون آرگومان (No-argument Constructor):**
    
    ```Java
    Rectangle rect = new Rectangle();
    ```
    
    این سازنده هیچ ورودی‌ای نمی‌گیرد و مقادیر پیش‌فرضی را برای مستطیل در نظر می‌گیرد.
    

#### نکته مهم درباره سازنده پیش‌فرض (Default Constructor):

تمام کلاس‌ها حداقل یک سازنده دارند. اگر شما هیچ سازنده‌ای برای کلاس خود ننویسید، کامپایلر به صورت خودکار یک **سازنده پیش‌فرض بدون آرگومان** ایجاد می‌کند. این سازنده، سازنده بدون آرگومانِ والدِ کلاس (Parent) را فراخوانی می‌کند. اگر کلاس والد (مانند `Object`) سازنده بدون آرگومان داشته باشد، برنامه اجرا می‌شود، در غیر این صورت کامپایلر خطا خواهد داد.

### تمرین با سازنده‌های مختلف (کلاس Student)

در مثالی که برای کلاس `Student` آورده شد، مشاهده می‌کنید که چگونه می‌توان با استفاده از سربارگذاری (Overloading)، انعطاف‌پذیری ایجاد کرد:

```Java
var student1 = new Student(); // خروجی: Unknown, 0, Undeclared
var student2 = new Student("Alice"); // خروجی: Alice, 18, Undeclared
var student4 = new Student("Carol", 19, "Computer Science"); // مقداردهی کامل
```

این روش به برنامه‌نویس اجازه می‌دهد بدون نیاز به دانستن تمام جزئیات یک شیء در لحظه ساخت، آن را با مقادیر حداقلی ایجاد کند.

### استفاده از اشیاء (Using Objects)

پس از اینکه یک شیء را ایجاد کردید، احتمالاً می‌خواهید از آن برای انجام کاری استفاده کنید؛ مثلاً مقدار یکی از فیلدهایش را بخوانید، آن را تغییر دهید یا یکی از متدهایش را فراخوانی کنید.

#### ارجاع به فیلدهای یک شیء (Accessing Fields)

فیلدهای یک شیء از طریق نامشان در دسترس هستند. شما باید از نامی استفاده کنید که **بدون ابهام** باشد.

- **نام ساده:** در داخل کلاس خودِ شیء، می‌توانید از نام ساده استفاده کنید. مثلاً در داخل کلاس `Rectangle`:
    
    `IO.println("Width is: " + width);`
    
- **نام واجد شرایط (Qualified Name):** کدی که خارج از کلاسِ شیء قرار دارد، باید از یک مرجع شیء (Object Reference) به همراه عملگر نقطه (`.`) و سپس نام فیلد استفاده کند:
    
    `objectReference.fieldName`
    

به عنوان مثال، در کلاس `CreateObjectDemo` برای دسترسی به عرض مستطیلی به نام `rectOne` باید بنویسیم `rectOne.width`. استفاده از نام ساده `width` در خارج از کلاس منجر به خطای کامپایل می‌شود، زیرا این فیلد متعلق به یک نمونه خاص است.

هر شیء کپی مخصوص به خود را از فیلدها دارد. بنابراین `rectOne.width` و `rectTwo.width` دو حافظه کاملاً مجزا هستند. همچنین می‌توانید از عباراتی که مرجع شیء برمی‌گردانند (مانند عملگر `new`) برای دسترسی مستقیم استفاده کنید:

`int height = new Rectangle().height;`

در این حالت، یک مستطیل ساخته شده، ارتفاع آن خوانده می‌شود و چون مرجع آن در هیچ متغیری ذخیره نشده، بلافاصله آماده بازیافت (Garbage Collection) توسط حافظه می‌شود.

---

#### فراخوانی متدهای یک شیء (Calling Methods)

مشابه فیلدها، فراخوانی متدها نیز از طریق مرجع شیء و عملگر نقطه انجام می‌شود. شما باید نام متد را به همراه پرانتزها (و آرگومان‌ها در صورت وجود) بعد از نقطه بیاورید:

`objectReference.methodName(argumentList);`

در مثال ما، فراخوانی متدها به این صورت است:

- `rectOne.getArea()`: محاسبه مساحت مخصوص `rectOne`.
    
- `rectTwo.move(40, 72)`: تغییر مختصات مبدأ مخصوص `rectTwo`.

اگر متدی مقداری را برگرداند (مانند `getArea`)، می‌توانید از آن در عبارات ریاضی یا انتساب به متغیرها استفاده کنید:

`int areaOfRectangle = new Rectangle(100, 50).getArea();`

### مدیریت حافظه و پاکسازی (The Garbage Collector)

برخی زبان‌های برنامه‌نویسی از شما می‌خواهند که اشیاء ایجاد شده را پس از اتمام کار، به صورت دستی از حافظه حذف کنید. اما جاوا این کار را به صورت خودکار انجام می‌دهد. سیستم **Garbage Collection** (زباله‌روبی) در جاوا، اشیائی را که دیگر هیچ مرجعی به آن‌ها وجود ندارد، شناسایی کرده و حافظه آن‌ها را آزاد می‌کند.

**یک شیء زمانی واجد شرایط حذف است که:**

1. متغیر مرجع آن به `null` تغییر یابد.
    
2. متغیر مرجع آن به شیء دیگری اشاره کند.
    
3. مرجع آن یک متغیر محلی در یک متد باشد که اجرای آن متد به پایان رسیده است.

### زباله‌روب (The Garbage Collector)

برخی از زبان‌های برنامه‌نویسی شیءگرا شما را ملزم می‌کنند که تمام اشیاء ساخته شده را ردیابی کرده و پس از اتمام کار، آن‌ها را به صورت دستی نابود کنید. مدیریت دستی حافظه کاری طاقت‌فرسا و مستعد خطاست. اما پلتفرم جاوا به شما اجازه می‌دهد هر تعداد شیء که نیاز دارید بسازید (البته تا جایی که سیستم شما توان پردازش داشته باشد) و نگران نابودی آن‌ها نباشید.

محیط زمان اجرای جاوا (JRE) زمانی که تشخیص دهد اشیاء دیگر مورد استفاده قرار نمی‌گیرند، آن‌ها را حذف می‌کند. این فرآیند **Garbage Collection** یا زباله‌روبی نامیده می‌شود.

#### چه زمانی یک شیء آماده زباله‌روبی می‌شود؟

یک شیء زمانی واجد شرایط برای زباله‌روبی (Garbage Collection) است که هیچ مرجعی (Reference) به آن وجود نداشته باشد. مراجع موجود در متغیرها معمولاً در دو حالت از بین می‌روند:

1. **خروج از محدوده (Scope):** وقتی متغیر از محدوده‌ای که در آن تعریف شده خارج شود.
    
2. **انتساب به null:** می‌توانید با قرار دادن مقدار ویژه `null` در متغیر، به صورت صریح مرجع را قطع کنید.

به خاطر داشته باشید که یک برنامه می‌تواند چندین مرجع به یک شیء واحد داشته باشد؛ برای اینکه یک شیء آماده حذف از حافظه شود، **تمام مراجع** به آن باید از بین بروند.

#### فرآیند زباله‌روبی

زباله‌روب در محیط زمان اجرای جاوا به صورت دوره‌ای حافظه اشغالی توسط اشیاء بدون مرجع را آزاد می‌کند. این سیستم کار خود را به صورت **خودکار** و در زمان مناسبی که خودش تشخیص دهد (معمولاً زمانی که حافظه رو به اتمام است) انجام می‌دهد.
