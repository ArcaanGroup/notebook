K&R در این بخش نشان می‌دهد که چگونه می‌توان کد تبدیل دمای فارنهایت (که در بخش ۱.۲ نوشتیم) را بسیار کوتاه‌تر کرد. دستور `for` یک شکل سیستماتیک و متمرکز برای مدیریت حلقه‌هاست.

### ۱. مقایسه کد `while` با `for`

برنامه تبدیل دما با استفاده از `for` به این شکل در می‌آید:

```c
#include <stdio.h>

/* print Fahrenheit-Celsius table */
main()
{
    int fahr;

    for (fahr = 0; fahr <= 300; fahr = fahr + 20)
        printf("%3d %6.1f\n", fahr, (5.0/9.0)*(fahr-32));
}
```

### ۲. آناتومی حلقه `for`

این دستور از سه بخش اصلی تشکیل شده که با سمیکالن (`;`) از هم جدا می‌شوند:

1. **مقداردهی اولیه (`fahr = 0`):** فقط یک بار در ابتدای شروع حلقه اجرا می‌شود.
    
2. **شرط (`fahr <= 300`):** قبل از هر بار اجرای بدنه حلقه چک می‌شود. اگر درست (true) باشد، حلقه ادامه می‌یابد.
    
3. **گام حرکت (`fahr = fahr + 20`):** پس از اجرای بدنه حلقه و قبل از چک کردن مجدد شرط اجرا می‌شود.

### ۳. تفاوت‌های فلسفی و فنی

نویسندگان کتاب به چند نکته مهم در این تغییر ساختار اشاره می‌کنند:

- **حذف متغیرهای اضافی:** متغیرهای `lower`, `upper` و `step` حذف شدند و مقادیر آن‌ها مستقیماً در دستور `for` قرار گرفتند (هرچند بعداً در بخش ۱.۴ می‌گویند که بهتر است از ثابت‌های نمادین استفاده کنیم).
    
- **انعطاف‌پذیری در محاسبات:** عبارت `(5.0/9.0)*(fahr-32)` مستقیماً به عنوان آرگومان سوم در `printf` قرار گرفته است. در C، هر جا که مجاز به استفاده از مقدار یک متغیر باشید، می‌توانید از یک **عبارت محاسباتی** هم‌نوع آن استفاده کنید.

> **قانون انتخاب K&R:** چه زمانی از `while` و چه زمانی از `for` استفاده کنیم؟
> 
> اگر حلقه دارای یک مقداردهی اولیه و یک گام حرکت مشخص (مثل شمارش) است، `for` انتخاب بهتری است چون تمام منطق کنترل حلقه را در یک خط جمع می‌کند و خوانایی را بالا می‌برد.
